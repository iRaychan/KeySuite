# KeySuite V5.00.82

Baseline: verified KeySuite V5.00.81 FULL (`d0118a1533695bf07f64737952912d633f01cdab9da95ba5af3c32b26e378183`).

## Bug 001 — quotation viewing

Frontend history, search, cache exposure and direct load use the existing role permission matrix through one Full/Own/None resolver. Legacy `all` is read as Full and legacy `assigned` as Own for quotations only. The role editor offers only None, Own and Full. Customer permissions remain independent; creation and deletion settings are not elevated. Non-owner history loading no longer attempts automatic duplicate deletion.

**Database dependency remains:** the live history RPC is owner-only. A reviewed proposal is included but unapplied. Bug 001 is not complete in production; see `V5.00.82_DATABASE_DEPENDENCIES.md`.

## Upgrade 002 — category filter

Added compact case-insensitive begins-with filter and Clear control above the left category list. Results keep A–Z sorting; filtering does not refill the right editor or discard its selected category/unsaved values.

## Bug 003 — partial Pumpset

Validation checks each selected positive-quantity component. Empty Motor/Coupling/Baseplate sections are not mandatory. Partial conversion does not insert absent accessories; explicit Complete Set retains its automatic component selection. Removed baseplates remain excluded, and explicit Restore Auto Coupling remains available.

Descriptions cover six partial configurations, Pump only and Complete Pumpset. Commercial brand/model, suction/discharge, material, actual motor description and pump motor sizing are used dynamically. Partial descriptions use Flexible Coupling and name excluded components as customer supplied. Existing complete-set mode-specific coupling wording is retained. Pricing functions, margins, shared fuel calculations and inventory keys are unchanged.

## Upgrade 004 — payment terms

Added vertically stacked Cash, To be advised, As usual and Custom Terms checkboxes, with only one selected at a time. Custom wording appears when selected and cannot be saved blank. PDC remains separate. Cash sets days to zero; special options take precedence over credit/PDC wording while retaining the stored PDC choice. Ordinary positive credit days and existing PDC format are preserved; zero days with no special option defaults to Cash before delivery (legacy PDC-only records remain PDC).

Special selections persist using a versioned value in the existing `payment_terms` text column, preserving days/PDC/custom wording without new columns. New quotations inherit the decoded wording; template defaults do not override customer terms. Saved quotation payment text is retained when customer contacts/settings refresh. Older clients do not understand the special encoding; update clients before using new terms and review downgrade compatibility.

No deployment, GitHub push, production writes, migration or data reset was performed.
