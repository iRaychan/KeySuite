# Root-cause findings

## 001 — confirmed frontend and server restrictions

`app.js` used `canManageQuotationHistory()` (literal Owner role) in `visibleQuotationRows`, history user filtering and rendering. Admin Full was therefore filtered to its own creator email. The role editor also offered legacy Assigned, contrary to the requested three-level quotation model.

Read-only inspection of live `keysuite_list_quotations_v42919(text)` confirmed the same Owner-only condition inside its SECURITY DEFINER body. The frontend cannot retrieve rows the RPC omits. RLS is enabled on both quotation tables; no direct SELECT policies were returned. The existing secure gateway, rather than customer viewing policy, is responsible for company quotation history. Changing customer permissions cannot repair that gateway.

Responsible paths: `permissions.js`, `roles.js`, `app.js` (`quotes`, `visibleQuotationRows`, `filteredQuotes`, `quotationHistoryFilters`, `loadQuote`, `listRemoteQuotes`) and the approval-required history RPC proposal. Backend approval is still required. Legacy gateway grants need a separate compatibility/security review before claiming server-wide None enforcement.

## 002 — absent list-only filter

`categories.js:renderRows` rendered all sorted category records. A filter was not implemented. The correction filters that displayed array and binds input/reset directly to `renderRows`, leaving `fill`, selection and editor state untouched.

## 003 — mandatory sections and complete-only description branch

`assembly.js:missingPumpsetSourceCosts` iterated Pump/Motor/Coupling/Baseplate and treated missing rows as missing prices. It also examined only the first row in each section. `completedPumpsetDescription` required Motor and (for ES) Coupling, so partial sets fell back to concatenated descriptions instead of explaining supplied/excluded components. Automatic baseplate/coupling synchronization could repopulate absent accessories during render/read.

The correction validates selected rows, preserves intentional exclusion, and uses the existing formatter entry point for all combinations. `pumpDescriptionParts` retains commercial mapping for ES/ISO and uses the actual pump-type line for other families. No source-cost/margin calculation engine was replaced.

## 004 — numeric normalization discarded non-credit wording

`normalizeCustomerRecord` converted every `payment_terms` value into numeric days plus PDC. `remoteCustomerPayload` only wrote days/PDC. Customer form/state had no special-term option. Additionally `refreshQuotationContacts` and template defaults could overwrite payment wording after a customer change or general refresh.

`payment-terms.js` provides one versioned codec for existing storage. `app.js` uses it for loading, saving, display and new quotation inheritance, preserves saved payment strings, and keeps template payment defaults subordinate to a chosen customer. The existing unrestricted text column avoids a schema migration. Production persistence and actual PDF rendering remain unverified.
