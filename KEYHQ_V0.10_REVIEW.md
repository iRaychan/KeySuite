- Existing private chat/social PostgreSQL suite: **32 checks passed** (message permissions, receipt rules, nonce, presence, invitation consent and capacity).
- Existing social adapter tests passed (cleanup, stale-session discard, retry/conflict); existing avatar-sync tests: **7 passed**.
- Activity/vehicle simulation passed: all three two-player racket sports, swimming exit, all four vehicle occupancies/movement/exits. Office-to-activity movement maximum measured step: approximately **0.11m per 50ms**.
- Elevator queue/manual test passed with five passengers, four-person capacity and all four actual stops available.
- Exact hoop pivot tests passed with independently computed world-space intersections. World-space pan and empty-space click checks passed.
- Changed JavaScript modules pass `node --check`; packages are checked for removed runtime dependencies and baseline business-file integrity.

Two historical, unrelated suites fail identically on the supplied V0.9 baseline and this working copy: `v42920-release-regression.cjs` expects an obsolete 4.29.21 version; `v42865-functional-regression.cjs` expects an older PDF raster-cache implementation. They were not altered to manufacture a passing result. The affected business files are unchanged.

## Limitations and rollout acceptance still required

1. No production deployment or live Supabase data changes were performed. Existing account credentials were not used for testing. Real hosted websocket delivery, reconnect behavior, offline receipt across two signed-in accounts, group administration and ride invitations still require staging/approved account-level acceptance.
2. Character and sports animation are original procedural stylized assets. They are functional skeletal motion and projectile rallies, not motion-captured athletics or a competitive rules/scoring simulator. Visual quality is a reviewable interpretation of “Memoji-inspired”; the supplied preview images show it directly.
3. Offline autonomous activity remains local presentation, as in the supplied architecture. It is not a claim about an employee's real activity. Accepted social sessions and ride states are shared through Supabase; arbitrary walking/idle poses are not a new global telemetry service.
4. Collision tests cover the implemented campus routes, furniture, stationary coworkers, elevator queue and parked/driven vehicles. Dense simultaneous crowds, long multi-client sessions, older iPhone hardware and every unusual camera/geometry interaction have not been exhaustively stress-tested. WebKit automation is Safari-engine coverage, not certification of every Safari device/version.
5. PDF handoff/return state is tested with the local host fixture. The existing real KeySuite permission-checked PDF renderer is unchanged; authenticated end-to-end PDF download/printing should be included in rollout acceptance.
6. Group administrators cannot remove themselves or leave the group; they can add/remove other members and rename it. Administrator transfer and group deletion were not requested and are not added.

## Database requirements

Apply only after approval: `supabase/migrations/20261024184425_keyhq_v010_groups_rides.sql`. See `README_UPGRADE_KEYHQ_V0.10.md` for dependencies and rollout steps. The migration creates group/membership/message/ride tables, RLS/grants and private-schema authorization routines exposed through security-invoker wrappers. Existing social capacity/consent logic is extended, not bypassed. Realtime is enabled for the new tables when the publication exists.

Security review followed the installed Supabase skill and current [RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security) and [Realtime/Postgres Changes guidance](https://supabase.com/docs/guides/realtime/postgres-changes). Current changelog was inspected. No new runtime dependency on a different Supabase client version was introduced.
