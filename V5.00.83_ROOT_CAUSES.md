# Root causes

## Bug 001 — confirmed in source

`v40001-customer-brand-settings.js:rawPriceEntries` generated Selection checkbox links from fixed per-family cases. The generic G price row had an empty selectionKey. `isSelectionAllowed` also rejected G through a fixed whitelist. `v50033-series-registry.js` filtered non-master mappings through another fixed supported list.

The correction uses `KeySuiteV391.brandFamilies` as commercial discovery for the shared registry, connects those entries to the existing customer price rows, and uses the same registry to determine selection eligibility. Existing CHC legacy keys remain compatible. Commercial labels remain separate from hydraulic sources. New series must have an eligible configured commercial navigation entry/engine; this does not invent a hydraulic engine for arbitrary names.

## Bug 002 — confirmed by comparison with V5.00.81

V5.00.82 added absence-based writes to `assembly.js:syncAutomaticComponents`: no coupling/baseplate row became a persistent auto_suppressed flag before automatic sizing ran. A fresh draft was thus treated as an intentional deletion. V5.00.81 did not infer suppression this way.

Remove that inference and preserve existing sizing functions. Explicit Delete and Restore determine suppression. `quoteMeta` previously omitted baseplate suppression; it now persists it alongside coupling suppression. A Baseplate Restore control completes the existing removal workflow.

Existing true flags are ambiguous and are not cleared automatically. User restoration is required for affected old drafts. No pricing, hydraulic or catalogue lookup engine was changed.
