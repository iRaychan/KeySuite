# V5.00.84 root causes and recovery

## Recovery

The interrupted workspace was available. Its verified V5.00.83 FULL ZIP has SHA-256 `e887bdac427a9bc09a10df8932657bf6dd5b50d6d334ccc135f6830dba2cd69f`, matching the previously delivered package. Recovery found 21 changed baseline files and two added files: operating-speed.js and tests/v50084.cjs. No FULL/UPGRADE V5.00.84 archives existed.

The valid frequency changes were retained. Outstanding test-harness issues included JSDOM's missing structuredClone, local resource-loading failures, private ES/ISO functions and a mistaken BEP test-field path. These were resolved in test code. The final shared control rejects, rather than silently caps, an entered value above 60 Hz.

## Upgrade 001 — confirmed source findings

The selector HTML pages independently clamped Hz to 50, limited RPM to 2900 and rounded unit changes to one decimal. Product-duty handlers and validation also imposed 50 Hz. G's curveFit/plot rejected frequencies above 50. ES/ISO rounded manual frequency in both the UI and applyFlexibleSetting; their off-50 curve display used a tolerance that classified 50.01 as 50 Hz.

operating-speed.js now owns frequency bounds, unit conversion, decimal preservation and input highlighting. Existing engine adapters call it, validate their frequency entry points and retain their existing affinity calculations. ES/ISO no longer round away 50.01 Hz and display its separate operating curve.

## Bug 002 — confirmed source findings and isolated reproduction

1. commercial-identity.js stamped descriptions at quoteItemRow creation, but app.js addExternalQuoteItem subsequently assigned the original incoming description to the textarea. The later family whitelist only repaired some combinations and ignored an identity-only payload. An isolated execution of V5.00.83 reproduced a VEC identity snapshot yielding the raw B.G.Reich description.
2. CHC's direct selector message route populated an existing/blank row rather than consistently calling the shared identity boundary. Commercial context could be inferred after showPage changed global state.
3. v40001-multibrand.js mapRowIdentity immediately returned for rows containing commercialIdentity. Thus a valid snapshot prevented legacy correction after the textarea had been overwritten. Its external-item wrapper could also choose a default pricing/master brand as the commercial fallback.
4. assembly.js addItem constructed a new item with selected fields and omitted commercialIdentity. Later formatting could use current/default brand metadata instead of the item's captured selection.
5. quoteItemBrands recursively gathered source-pricing brand names even when the item had an authoritative commercial snapshot, allowing a source brand to leak into quotation/PDF brand lists.

## Central correction

commercial-identity.js now resolves/captures selection identity and reapplies it at final row boundaries. The CHC message handler captures it before navigation; addExternalQuoteItem and the legacy wrapper keep the normalized data and final textarea consistent. Assembly constructors retain snapshots, and shared rebuilding normalizes component descriptions without replacing mixed-system brands. Manual edits and restored legacy rows without snapshots are protected. Hydraulic payloads, source-price models and costing formulas remain separate and unchanged.

Tests exercise the actual app listener, external-item handler, real configured mapping resolver, legacy wrapper, assembly formatting, quotation serialization/history reopening via an isolated RPC mock, and print DOM. The live Safari scenario was not reproduced: no supported desktop/browser-control capability was available, and AppleScript could not resolve/connect to com.apple.Safari. Screenshots are user-provided evidence; they are not a claimed browser inspection.
