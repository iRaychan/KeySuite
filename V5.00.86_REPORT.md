# KeySuite V5.00.86 completion report

Built from the supplied V5.00.85 Corrected FULL. KeyStock is now V1.04. Development and local verification only; no GitHub push, deployment, production migration or production data change.

## Implementation

Four adjacent Finder columns retain horizontal scrolling. Critical/Normal options are shared once per series. CHC C4 and C6 remain separate. Pricelist Link now manages shared dropdown arrangements, their selection options and exact saved combinations. Existing model arrangements remain separate: a series containing active legacy model arrangements requires explicit reconciliation before shared arrangements can be created. No automatic copying or old-data restoration occurs.

The gateway enforces tenant permissions, stable identifiers, revision conflicts, duplicate names/combinations, complete selections, valid existing codes and each received model's actual applicability. Referenced options/arrangements cannot be removed. Mapping edits/deletions affect future receipts; historical stock configurations retain their recorded variant. New shared mappings cannot silently receive stock as “Unmapped.” Future model exceptions retain a distinct model scope; an overlapping model/shared arrangement is rejected instead of guessed.

## ES check

The supplied build's catalogue function still restricted ES to six codes. Its bundled catalogue fixture contains ten distinct ES materials. A read-only check on 23 November 2026 found eleven materials in the current live Pricelist and six exposed by live KeyStock. The new catalogue wrapper reads the actual material list for each model, without changing prices or inventing codes.

The bundled fixture has 2,587 models; the current live catalogue returned 2,631. This release does not replace or seed that catalogue and does not force the old count. Local tests use the supplied 2,587-model fixture; production data were not copied into or overwritten by the test database.

## Limits and rollback

Database writes/tests used an isolated PGlite PostgreSQL environment with simulated authenticated roles. Live Supabase Auth/PostgREST save behavior must be checked in staging before production rollout. The browser review used the in-app browser; native Safari and fresh PDF exports were not rerun for this KeyStock-only change. Quotation/PDF code is unchanged and the identity/quotation regression suites passed.

The migration is required before using Pricelist Link in production. Keep a verified database/application backup before future approval to deploy. The supplied automatic rollback is for before-use only and refuses a lossy downgrade after shared linked setup or newly exposed ES stock configurations exist. Full rollback details are in `README_UPGRADE_V50086.md`.
