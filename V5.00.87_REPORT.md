## Confirmed failure and cause

Production PostgreSQL logs previously captured SQLSTATE 57014 in the PostgREST call to `public.keysuite_list_quotations_v42919(p_company_id text)`, including 24 November 2026 at 16:14:39 Malaysia time. The installed definition and V5.00.86 source confirm that this path combines archive/current full JSON documents, ranks duplicate references, loops over winning documents for creator visibility and returns the full documents without internal pagination. PostgREST then aggregates them into JSON.

The application invoked that unbounded read on initial history load, after saves, and around deletion. The history loader also attempted automatic duplicate cleanup. That cleanup has been removed from the read path; intentional deletion still uses the existing secured RPC.

This is an architectural retrieval and payload problem, not an established missing-index problem. Existing company/reference/date/creator indexes were already present. The earlier read-only snapshot found about 100.7 MB of stored quotation JSON across both source tables. Historical `pg_stat_statements` recorded 229 calls averaging 6,119.49 ms, maximum 7,953.21 ms; these are aggregate historical measurements, not today's latest latency or failed-call durations. A later targeted read confirmed the installed history definition fingerprint `fcc3f4e21832783c620f8af243b035bd`.

The removal of full JSON processing from list reads is verified in code and isolation. An exclusive production internal bottleneck (IO versus JSON detoasting/serialization, permission helpers, or concurrent load) has not been established by a production execution profile. No database timeout setting was increased.

## Changes

- Add a derived, RLS-enabled summary table, with direct access revoked from Public/Anon/Authenticated. Source insert/update/delete triggers maintain it within the same transaction; a one-time backfill reads source documents without changing them.
- Server-side keyset pagination: 50 rows per app page, maximum RPC limit 100. Sorting uses quotation/revision date, numeric quotation sequence, revision, normalized creation/update time, reference and logical identity. Identical reference winners retain the original latest-update/current-source priority before user filtering.
- Search quotation number, customer, both project fields and all item model/product/family fields across the full authorised summary dataset. Dates/customer/user filters run server-side. Global years, creators, metrics and latest-five summaries remain available independently of the displayed page.
- Open, PDF and KeyHQ PDF fetch one full document through a company- and permission-checked RPC. Existing item data, brands, pricing, templates, signatures, revisions and audit are retained. Summary records cannot be sent to save as if they were complete documents.
- Existing save RPC remains unchanged. The app trusts its explicit atomic saved-document acknowledgement, then refreshes summaries; failed acknowledgements reject. Revision creation checks sibling summary pages before choosing the next revision number. Production concurrency/number allocation remains governed by the existing save RPC.
- Serialise list/Retry calls, ignore obsolete responses, disable paging while loading and debounce filter inputs. No uncontrolled automatic retries and no fallback to bulk legacy history reads.
- Keep full quotation backups, legacy backup keys and drafts intact. Store summary backups separately by company/account; merge read data locally without uploading it. Failed refresh clearly labels the backup incomplete/outdated and shows the last successful history retrieval time when available. This timestamp does not certify that every quotation document was downloaded.
- KeyHQ's existing complete quotation picker explicitly pages through summaries on demand; normal history loads only one page. PDF still downloads only the selected full document.

## Verification limits and outstanding checks

- SQL projection/backfill, actual source inserts/updates/revisions/deletes and rollback were executed in PGlite, not production. App save/Retry tests use an isolated mocked RPC contract; the existing production atomic save function was not exercised with production writes. Cross-device consistency was simulated using two independent client contexts over the same test source, not two real production devices.
- Actual print DOM contents and full-document PDF hydration were tested. Native Safari/Windows PDF output and real printer/browser rendering still require manual verification.
- Full substring search and global facets use narrow summary metadata. They do not read source JSON on list requests, but still require processing matching authorised summary rows. Further indexing should follow measured production plans if the dataset grows substantially.
- Concurrent changes can move a quotation between keyset pages; use Retry/Clear Filters for a fresh traversal. No point-in-time snapshot across multiple page requests is promised.
- Large full documents are still downloaded when explicitly opened or printed. Projection maintenance adds work to source writes; production write overhead remains to be measured.
- No stale local quotation was uploaded or reconciled into production. Any recovery of local-only records needs separate approval after comparing IDs, references, revisions and timestamps.
