# KeyStock V1.00 confirmed design requirements

V5.00.53 is a Phase 2 review build from the supplied V5.00.52 full build. The installed KeyStock runtime remains V1.01, with the Phase 1 database contract.

| Requirement | V5.00.52 audit | V5.00.53 status |
| --- | --- | --- |
| Main sidebar | KeyStock position correct. Cyan styling and cube icon missing. | Fixed and browser tested as Phase 2 Bug 001. |
| KeyStock left panel | Five horizontal tabs. Several specified modules absent. | Pastel panel and six named destinations in the approved relative order. Dropdown Management uses the existing server Owner/Admin gate and is hidden from other roles. Add Stock awaits its receiving workflow and separate permission. Existing stock tools remain reachable. |
| Stock Check search | Model/brand, product family and stock status available. No location/supplier/serial filter combination. | Live model search plus location-prefix and searchable supplier filters. Family and stock-status filters remain available. Serial search awaits the ledger. |
| Stock Check main results and details | Expandable configuration summaries. Selecting a model opened Stock Input. | Requested five-column result, separate model detail, four summary boxes, normal group quantities and return to prior filters. Reserve and Not Complete are shown as unavailable. On Hand is the recorded physical opening-balance quantity. |
| Stock Check batch breakdown | Configurations grouped by location. Separate source entries existed in history. | One row per active opening balance. Dynamic normal-group columns, recorded variant, centered values, and both date sort orders. The date is the existing opening-entry timestamp. Add/adjust, reserve and deduct controls await permissioned ledger actions. |
| Missing Parts | Opening entries had manually recorded critical shortages. No requirements or shared component allocations. | Searchable recorded shortages by model, series and component. Required, available and affected quantities are unknown. Actual calculated shortages and double-allocation prevention need component definitions and a ledger. |
| Reservations | No reservation ledger or customer-linked stock workflow. | Destination identifies the missing ledger. Creation, customer lookup, partial fulfillment, serial checks, release, idempotency and audit require new server actions. |
| Stock Movement | No movement view or transaction ledger in the supplied build. | Time Frame control defaults to a collapsed Last 30 Days and preserves selection. Stock out, customer return, write-off, transfers and reconfiguration require a ledger. The actual movement form layout was not present in the supplied references. |
| Stock History | Per-model opening balance history, including corrections. No serial or lifetime transaction history. | Searchable opening and correction history, collapsible time filters and per-model physical stock totals. Purchases, delivery totals, serial history and other movement types are unavailable pending the ledger. |
| Add Stock | One opening-entry form with existing catalogue validation, batch records and cost permissions. No atomic multi-row purchase receipt or explicit receipt date. | Existing opening-balance records and maintenance remain available under their original server permission. The new receiving form, separate Add Stock permission, single multi-row flow, date, collapsible sections and short-model resolution require the next implementation. |
| Dropdown Management | Model-scoped Normal, Critical and Pricelist Link groups and editors. No four-column combined filter. | Four-column overview with four simultaneous filters and links to the original model editor. Existing groups, options and mappings stay intact. Series-level inheritance and a separate dropdown permission require schema/API work. Existing catalogue labels reflect the supplied data. |
| Batch costs and FIFO | MYR purchase cost stored per opening entry with server access controls. No stock issue ledger. | Cost records and access rules carried forward. FIFO for issue and cost/date preservation through transfer require ledger actions. |
| Pricelist and quotation pricing | Existing mapping and quotation behavior in the baseline. | ES/CHC mapping fixes, automatic substitution and the future quotation-cost comparison are deferred. |
| Permissions and audit | Approved tenant-scoped access, several maintenance permissions, legacy Owner/Admin authority, separate cost access and an existing audit log. | Existing rules retained and tested. Separate View Stock, Add Stock, Manage Dropdowns, Reserve, Confirm Stock Out, Adjust and Transfer/Reconfigure require API enforcement and role settings before activation. |
