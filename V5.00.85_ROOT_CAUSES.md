# Root-cause analysis

## Bug 001: classification leaked into commercial identity

The V5.00.84 shared resolver selected `mainSellingSeries`/`brandSeries` when `sellingSeries` equalled the hydraulic family. B.G.Reich's CHC navigation labels are intentionally CHC C4/CHC C6, so a correctly named CHC model could become CHC C6 10-4. Commercial model prefix resolution now uses the explicit selling series and never a navigation label.

Separate entry routes supplied differing brand/model metadata. Product C4's direct sender carried `keysuite_selling_brand_id`/`keysuite_selling_model`, while the shared capture previously read only `keysuite_brand_id`. It also deferred capture until after `postMessage`, allowing navigation/global state to affect identity. The sender now captures the same immutable identity snapshot used by the Curve route. An explicit current brand beats a stale frame pin; explicit brandless presentation data beats a pricing-source brand.

The shared resolver now also handles component metadata and descriptive `Model:` labels. Stamping preserves raw hydraulic payloads and pricing snapshots; it updates customer-facing item/BOM models and descriptions. Costing display stamps a presentation copy rather than mutating source amounts. Source catalogue brand constants in the G and BGF producers no longer override the selected commercial identity. Other product adapters capture through the same API. The grouped Pumpset formatter also used generic coupling/baseplate wording that discarded selected component identities; it now formats those supplied components through the shared resolver while retaining the existing customer-supplied missing-component rules. This is a shared pipeline repair, not a VMS-specific string substitution.

## Bug 002: adding an item selected the brand template

`stampRowBrand()` explicitly called `KeySuiteTemplates.selectForCustomer(brand.quotation_template_id)` whenever the quotation had one row. It ran while the first product was added, replacing a selected Keylargo template with TESK when that brand had a TESK template configured. That call has been removed. Customer/template selection continues through the existing explicit customer and template UI handlers.

The Product List and Curve routes differed in when they captured identity and when legacy row branding ran. Both now carry the shared commercial snapshot, and the legacy alias adapters delegate CHC as well as other families to the shared module. Row writes restore the captured commercial identity after technical pricing is applied.

## Hydraulic duty difference

The quote handler consumes duty values from its own payload. Tests send a 30 m Curve payload and a separate 36 m List-transport payload and verify each is retained. The C4 direct List route legitimately has no selected duty point. No hydraulic formula has been changed to force those routes to the same duty point.

## Reproduction and limits

The new isolated application harness fails against the supplied V5.00.84 source because adding the first product changes `standard:isolated` to `tesk-template`. The original resolver separately returns CHC C6 10-4 for the internal C6-label fixture. Both checks pass with V5.00.85. Full logs and test sources are included. Cloud Browser cannot reach the local fixture; native browser/PDF download behavior is not represented as verified.
